05 · How I Build

Diagram first. Then code.

Before touching an editor I sketch the whole workflow on a canvas. Once I can see every box and arrow, the code is mostly translation.

  1. 01

    Sketch the workflow

    Map the whole system on a tldraw canvas — actors, screens, data and where things can go wrong.

  2. 02

    Break it into steps

    Turn every box into a small, testable unit with a clear input and output.

  3. 03

    Then write the code

    Build one unit at a time, commit after each, and check it against the diagram.

Idea

02

03

04

06

Automated where possible.

06 · My Claude Workflow

AI-augmented development — Claude Code CLI as a tool, not a crutch.

I stay the engineer: I plan, review and own every change. Claude Code speeds up the typing, and the setup below keeps it disciplined, cheap on tokens and easy to roll back.

Git & GitHub discipline

Every project gets its own repository from day one. Each unit of work becomes a clean commit pushed to GitHub, so there is always a saved version to revert to.

  • New repo per projectIsolated history, nothing tangled.
  • Clean commit messagesHistory you can read months later.
  • Push after each unitStatus is never lost; revert anytime.
Kick-off prompt“From now on, I would like you to make a new Git repository for this project. Make clean commit messages, save them locally and then push them to GitHub, so that we always have a saved version of the project and it's easier for us to revert back in case we make any changes.”
Then — write it into CLAUDE.md“Update the @CLAUDE.md file to indicate that as you do work you need to commit things to Git and push them to GitHub with clean commit messages so we never lose the status or work that we have done.”
bash · the loop
git add -A
git commit -m "feat: add level select screen"
git push
bash · roll back a bad change
git log --oneline
git revert <commit-sha>

Caveman — fewer words, fewer tokens

A Claude Code plugin that makes Claude answer in terse "caveman" style. Same work, far shorter replies — so a session goes further before hitting limits.

bash
claude plugin marketplace add JuliusBrussee/caveman
claude plugin install caveman@caveman

Source: github.com/JuliusBrussee/caveman

Graphify — a project knowledge graph

Graphify maps a project into a knowledge graph Claude can query, instead of re-reading every file. Less context to load means fewer tokens. It works on any folder — a codebase, notes, papers.

bash · install
pip install graphifyy && graphify install
bash · or isolate the CLI with pipx
pipx install graphifyy && graphify install
claude · inside a session
/graphify .

Source: github.com/safishamsi/graphify

Karpathy-inspired guidelines — one CLAUDE.md

A single CLAUDE.md file, derived from Andrej Karpathy's observations on LLM coding pitfalls, that sets four principles for how Claude should work. I append it to the project's own CLAUDE.md.

bash
echo "" >> CLAUDE.md
curl https://raw.githubusercontent.com/forrestchang/andrej-karpathy-skills/main/CLAUDE.md >> CLAUDE.md

Source: github.com/forrestchang/andrej-karpathy-skills

The .claude folder

Every project gets the same structure, so Claude always knows where its team, commands, rules and skills live.

.claude/
├── agents/      ← AI team members
├── commands/    ← custom slash commands
├── hooks/       ← rules Claude MUST follow
├── rules/       ← context-aware instructions
├── skills/      ← situational intelligence
└── settings.json ← the control center
CLAUDE.md         ← the project brain (root)
  • agents/code-reviewer, debugger, test-writer, refactorer, doc-writer, security-auditor
  • commands/fix-issue, deploy, pr-review
  • hooks/pre-commit, lint-on-save
  • rules/frontend, database, api
  • skills/frontend-design/SKILL.md
bash · scaffold it
mkdir -p .claude/{agents,commands,hooks,rules,skills/frontend-design}
touch .claude/agents/{code-reviewer,debugger,test-writer,refactorer,doc-writer,security-auditor}.md
touch .claude/commands/{fix-issue,deploy,pr-review}.md
touch .claude/hooks/{pre-commit,lint-on-save}.sh
touch .claude/rules/{frontend,database,api}.md
touch .claude/skills/frontend-design/SKILL.md
touch .claude/settings.json CLAUDE.md
chmod +x .claude/hooks/*.sh

claude-mem — persistent memory across sessions

A Claude Code plugin that captures what happens during a session, compresses it with AI and brings the relevant context back next time. No more re-explaining the project every morning.

  • CapturesWhat Claude did during the session.
  • CompressesInto short, reusable memory.
  • RestoresRelevant context in future sessions.

Source: github.com/thedotmack/claude-mem · Docs: docs.claude-mem.ai

Hooks — rules the harness enforces

Hooks run my scripts at fixed points in Claude's lifecycle, so guardrails don't depend on the model remembering them.

Hook eventWhen it firesExample use
PreToolUseBefore any tool runsBlock dangerous commands
PostToolUseAfter a tool succeedsRun linters, format code
PermissionRequestUser sees a permission dialogAuto allow / deny
Notification★Claude sends a notificationSlack / Discord / SMS alerts
UserPromptSubmitUser submits a promptValidate prompts, inject context
StopClaude finishes respondingCheck tests
SubagentStopA subagent finishesSame as Stop, for agents
PreCompactBefore context compactionSave a transcript snapshot
SessionStartSession begins or resumesSet environment variables
SessionEndSession endsLogging, clean-up
